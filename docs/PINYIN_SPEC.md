# HSK listening vocabulary trainer — spec (v2)

Sibling of `hsk_characters.html` (HSK 1–3 characters). **Goal: understand spoken Mandarin (dramas, conversation).** The app teaches the **HSK 2.0 vocabulary, levels 1–4** (~1200 words) as *sounds with meanings*: the learner hears or reads pinyin and recalls the meaning. Characters are optional. Tones and pinyin spelling are a passive aid, not the subject. Same product strategy as the character app: placement → teach → drill → test → review, run as short daily sessions.

v1 (2026-09-16) was pronunciation-centred (word → pinyin, tone patterns, typed pinyin). v2 re-centres on meaning. Keep the engine, data, build, and UI shell; change the item types, session, placement and copy.

Output: `index.html` = `hsk_pinyin.html`, one self-contained file. Phone-first, no backend, works offline after first load. Progress in localStorage.

## Assumptions
- Audio = browser `speechSynthesis`, `zh-CN` voice. No audio files.
- Learner may know zero characters. Characters are hidden by default (global toggle "Show characters" in Progress and on word cards); when shown they sit small beside the pinyin, never as the only cue.
- HSK 2.0 (old 6-level system).

## Data
Unchanged from v1: `data/hsk_vocab.js` (`{w,py,n,en,lv}`), `data/pinyin_lessons.js` (foundations, now optional content). Order within a level ≈ frequency; sets = chunks of 10.

## Engine
Unchanged: drill runner (queue, requeue misses, score, keyboard 1–4/Enter/Esc), progress store `{v:2, w:{word:{r,w,s,prov,d}}, sets, lessons, sessions, theme, showChars, placedOnce, soundsOpened}`, mastered = streak ≥ 3, weakest-first, provisional priority, export/import with validation. Migration: v1 progress loads as-is (`v` bumped to 2, `showChars` defaults false), via the shared `PC.migrateProg`. (`dismissedSoundsHint`, from an earlier "Got it"-button version of the Today hints, is no longer written but still validated on import so an old export doesn't get rejected.)

### Item types (meaning-centred)
- **hear** — TTS plays the word (auto-play on mount + replay button); shown: nothing but "What does it mean?" → pick the meaning (4 options). Reveal: pinyin (tone-coloured), meaning, characters if enabled.
- **read** — pinyin shown (large, tone-coloured) → pick the meaning (4 options). Reveal as above + audio auto-plays.
- **recall** — meaning shown → pick the pinyin (4 options). Reveal + audio.
Distractors (meaning options) = 3 other VOCAB words: prefer same level; never same `en`; avoid glosses sharing the first word with the answer (e.g. two "to …" verbs are fine, two "to eat"-like near-synonyms are not: reject if the first 2 words of the gloss match). Pinyin options for recall = 3 other VOCAB words with the same syllable count, prefer same level (v1's phonetic near-miss generator is NOT used here — those confuse rather than teach meaning).
Retired from the core: tone-pattern items, typed-pinyin items, the phonetic distractor generator (keep the helpers in core for the optional Extras test only).

### Screens (bottom tab bar, 5 tabs)
1. **Today** — plan + "Start today". Steps: Review (15 weakest/provisional, mixed hear/read/recall ≈ 50/25/25) → Learn (next set of 10: teach cards = pinyin + meaning + play button, characters if enabled; then drill 10 × hear + 10 × read) → Listen (12 hear items from learned) → Recall (8 recall items from learned) → summary. Path strip: HSK1 → HSK2 → HSK3 → HSK4 (Sounds removed from the path; Phase 3b inserts character stages and changes Review/Learn/Recall once characters start — see Phase 3). First-time hints act directly rather than pointing at another tab: "New here? Placement finds where to start" with a **Take the placement test** button that starts placement immediately and returns to Today when it's done; "New to pinyin?" with a **Learn how to read it** button that opens Sounds lesson 1 immediately and returns to Today on back or done. Each hint hides once its own state is true (placement taken / any lesson opened) — no dismiss button.
2. **Words** — level chips, set pager, word list (pinyin + meaning, tap row to hear, characters if enabled), "Drill this set". Search box filtering by pinyin or meaning (new).
3. **Sounds** — v1 lessons + reference chart, unchanged but framed as optional ("Optional: how pinyin sounds and is spelled").
4. **Test** — Placement (40 vocab items only, hear/read → meaning, strata as v1, rolling-window rule; no foundations block) · Listen 20 · Recall 20 · Extras: Tones 20 / Type 20 (v1 items, from learned words).
5. **Progress** — per-level learned/mastered, sessions, weak words, Show characters toggle, export/import, reset.

## UI direction
As v1 (quiet palette, tone colour on pinyin, bottom tabs, pinned actions, dark mode, Plex Sans) with these changes: the hero of every drill is now the **meaning choice** — four large option buttons; the stimulus (pinyin or the speaker icon for hear items) is big and alone above them. Hear items show a large tappable speaker glyph with a subtle pulse while speaking. Copy: "What does it mean?", "Which word is this?", "You heard:".

## Acceptance
- All v1 acceptance items that still apply (loads clean, tabs render, session runs end to end, placement places, progress round-trips).
- Every drill in Today/Review/Placement/Listen/Recall is a meaning item (hear/read/recall); no tone or type items appear outside Extras.
- Characters never appear when `showChars` is false (grep-level check on rendered DOM in browser verification).
- Meaning distractors: never equal the answer gloss, never share the first two words, all from VOCAB; 200-word node check.
- v1 export imports cleanly.


## Phase 2 — Sentences (listening comprehension)

Data: `data/hsk_sentences.js` → `const SENTENCES=[{zh, py, en, lv, words:[...]}]` (~870 lines, generated from VOCAB tokens; validated by `tools/check_sentences.py`). Inline into the build like the other data files.

`words` tokens are VOCAB words plus a small whitelist of transparent compounds exported as `const SENTENCE_EXTRA={token:{py, base}}` (e.g. 夏天→夏, 哪儿→哪, 你们→你, 这个→这). Availability and per-word audio resolve an EXTRA token through its `base` VOCAB word; display uses the EXTRA pinyin.

Progress: `prog.s = {sentenceIndex:{r,w,s}}` keyed by `zh`; mastered = streak ≥ 2. A sentence is *available* when every word in `words` is in `learnedWords()` (or the learner has placed past its level). Weakest-first ordering as for words.

### Item types
- **hearSentence** — TTS plays the sentence (auto-play, replay glyph); shown: "What did they say?" → pick the English (4 options). Distractors = 3 other sentences of the same level with different `en`, preferring ones sharing ≥ 1 word with the answer. Reveal: pinyin (tone-coloured, word-spaced), English, characters if enabled; each word tappable to hear it alone.
- **readSentence** — pinyin shown → pick the English. Same distractors/reveal.
- **gapSentence** — pinyin shown with one content word blanked (a word of level = sentence level, not 的/了/吗/呢/是/我/你/他) → pick the missing word's pinyin (4 options: the answer + 3 VOCAB words of the same level and syllable count). Reveal + audio.

### Where sentences appear
- **Today** step 5 **Sentences** (after Recall): 8 items, hear/read/gap ≈ 50/25/25, from available sentences weakest-first; skipped with a one-line note when fewer than 8 are available.
- **Test** → **Sentences 20** (hear only) from available sentences; shows score and the missed lines with audio.
- **Words** → a word's reveal/teach card lists up to 2 sentences containing it (tap to hear).
- **Progress**: sentences available / mastered per level.

### Acceptance
- Checker passes on the inlined data; every `words` token resolves to a VOCAB entry at runtime (node check).
- Distractor English never equals the answer; gap word never a function word; gap options are valid VOCAB pinyin.
- Characters remain hidden when `showChars` is false (browser DOM grep as before).
- A Today session with sentences available runs the step end to end; with none available it skips cleanly.

## Phase 3 — Characters (recognition), as stages of the learning path (Phase 3b)

Goal: once the learner knows a band of vocabulary by sound, teach **recognition** of the characters of those words, and progressively swap sentence pinyin for characters as per-word character mastery grows. Characters come from VOCAB `w` only (no radicals/components). Never writing. (Phase 3 shipped characters as a separate daily step 6; Phase 3b, 2026-09-23, folded them into the learning path — see Deviations.)

Data/progress: no new data file. `prog.c = {[word]:{r,w,s}}` keyed by VOCAB `w` (same record shape as `prog.s`); a miss resets `s` to 0. Character **mastered** = `s ≥ 3`; **bare** (no pinyin in sentences) = `s ≥ 6` (`PC.CHAR_MASTERED`, `PC.CHAR_BARE`). `prog.mixChars` (boolean, default true) = mix known characters into sentences. Phase 3b adds two path flags: `prog.charsAfterHsk4` (boolean, default false) and `prog.charsChoiceSeen` (boolean, default false). Still `v:2` (purely additive). `PC.migrateProg` adds `c:{}` / `mixChars:true` / `charsAfterHsk4:false` / `charsChoiceSeen:false` when absent and changes nothing else; `validateProgShape` accepts `c` (same rules as `s`) and the three booleans. Boot migration also fires when any of them is missing; import keeps the current `mixChars` (like `theme`/`showChars`) when the import lacks it (the path flags default false); Reset clears `c`, restores `mixChars:true` and both path flags to false.

The Today choice card sets `prog.charsAfterHsk4` once but the choice is not final: a **learning order** control in Progress (Phase 3c) lets the learner flip it later too. It shows once HSK 1–3 are fully taught (same gate as `PC.showCharChoice`/`PC.charsUnlocked`), as two chips — "Characters before HSK 4" / "HSK 4 before characters" — with a one-line explainer underneath. Flipping the flag only changes what `PC.stagePath`/`PC.nextStage` compute next; it never touches `prog.c`/`prog.w`/`prog.sets`, so nothing already learned is lost either direction. A stage already snapshotted at "Start today" (`todayStepState`) is unaffected mid-session — the flip takes effect from the next "Start today" on.

### Learning path
The path is a sequence of stages (`PC.stagePath(prog, nsets, vocab)`), each shown as a segment of Today's path strip:

| order | stages |
|---|---|
| default | HSK1 → HSK2 → HSK3 → **字** (characters of HSK 1–3 words) → HSK4 → **字4** (characters of HSK 4 words) |
| `charsAfterHsk4` | HSK1 → HSK2 → HSK3 → HSK4 → **字** (characters of HSK 1–4 words, HSK 1 first) |

- **Word stage** fraction = sets taught / sets in the level (as before). **Character stage** fraction = words in its levels with a `prog.c` record / words in its levels.
- **Character sets** = chunks of 10 (`PC.CHAR_SET_SIZE`) of the stage's words in level order, then VOCAB (frequency) order (`PC.charSets(levels, vocab)`). A set counts as **taught** once every word in it has a `prog.c` record (`PC.charSetTaught`); there is no set counter. `PC.nextCharSet(levels, c, vocab)` = first untaught set.
- `PC.nextStage(...)` = the first incomplete stage in path order (`null` when everything is done). Today's step 2 **Learn** teaches that stage's next set. The stage and its set are snapshotted at **Start today**, so finishing a stage mid-session never changes what step 2 teaches that session.
  - Word stage: unchanged (teach cards, then 10 hear + 10 read; `prog.sets[lv]++`).
  - Character stage: teach cards for the set's 10 words (character large, pinyin, meaning, play glyph), then a 20-item drill: 10 pickChar + 10 readChar, scoring to `prog.c`. Finishing the drill leaves every word in the set recorded, i.e. the set is taught.
- **Skip choice** (one-time, `PC.showCharChoice`): when all HSK 1–3 sets are taught, HSK 4 is not complete, the 字 1–3 stage is incomplete (so it is the current stage), and neither `charsChoiceSeen` nor `charsAfterHsk4` is set (regardless of existing character records), Today shows a card in place of **Start today**: "Characters next — recognise the words you already know. Or skip to HSK 4 and do characters after." **Start characters** sets `charsChoiceSeen` only; **Skip to HSK 4** sets `charsChoiceSeen` and `charsAfterHsk4`, which reorders the path as in the table. Placement past HSK 3 lands on the same card on the first Today visit.

Gate: `charsUnlocked()` = `PC.charsStarted(prog, nsets, vocab)` = any `prog.c` record exists **or** the current stage is a character stage. It gates Test → Characters, the Progress character rows + mix toggle, sentence mixing, and character items in Review/Recall. Before that nothing character-related appears outside the path strip's static 字 labels, and sentence rendering is unchanged. (`PC.charsUnlocked(sets, nsets)` remains as "all of HSK 1–3 taught".)

### Item types
- **readChar** — characters shown large → "What does it mean?" → 4 meanings (`meaningOpts`). No pinyin, no audio in the stimulus.
- **charSound** — characters shown → "How is it said?" → 4 pinyin options (`pinyinOpts`).
- **pickChar** — audio auto-plays (speaker glyph to replay) + tone-coloured pinyin shown → "Which one is it?" → 4 character tiles. Distractors `PC.charOpts(entry, pool)`: 3 other VOCAB words, same level + same character count first, then same level, then any; never the same `w`, never the same `en`, never a homophone (same `n`).
- **recallChar** (Phase 3b) — meaning shown (large, as recall) → "Which character?" → 4 character tiles (`PC.recallCharOpts` = answer + `charOpts` distractors). Keyboard 1–4 via the shared MC renderer.
- Reveal (all four): characters, tone-coloured pinyin, meaning; audio plays on reveal for readChar/charSound/recallChar (pickChar already played it). Tap the reveal to hear it again. Scoring writes `prog.c` only.

### Today once characters have started
- **Step 1 Review**: provisional words first (as before, up to 5), then the weakest from a **combined pool** up to **20** items: every learned word (hear/read/recall ≈ 50/25/25, scored on `prog.w`) and every word with a `prog.c` record (readChar/charSound 50/50, scored on `prog.c`). One weakness score, `w*3 − s` over the respective record (`PC.weakScoreOf`, ranking `PC.rankReview`), except that an unmastered character (`s < 3`) scores `max(w*3 − s, 0)` (`PC.charReviewScore`), so fresh characters tie (random tie-break) with never-drilled learned words instead of ranking below all of them; mastered characters keep `w*3 − s`. A missed word outranks a fresh character; fresh characters outrank mastered words. Whether Review and Recall run in unified mode is snapshotted (`charsStarted`) at **Start today**. Before characters start: 15 weakest words exactly as before.
- **Step 2 Learn**: the current stage's next set (above).
- **Step 3 Listen**, **Step 5 Sentences**: unchanged.
- **Step 4 Recall**: 8 items drawn at random from a combined pool — one recall (meaning → pinyin) item per learned word plus one recallChar (meaning → character) item per word with a `prog.c` record. Before characters start: 8 weakest-first recall items exactly as before.
- No separate Characters step and no characters line in the session summary.

### Elsewhere (only once started)
- **Test**: **Characters N** (N = min(20, pool)) — readChar/charSound/pickChar 40/30/30 from words with `prog.c` records weakest-first, topped up with learned words (HSK 1 first, `PC.newCharWords`) when fewer than 20 have records; score + missed list (tap to hear), as Sentences 20.
- **Progress**: one row per character stage, "Characters HSK 1–3 / HSK 4 (or HSK 1–4): learned X / mastered Y of Z" (learned = has a `prog.c` record, Z = words in the stage's levels), and a chip toggle **Mix known characters into sentences** bound to `prog.mixChars`.

### Mixed-script sentences
Everywhere a sentence's word-spaced pinyin renders (`sentencePyHTML`: readSentence/gapSentence stimulus, hear/read/gap reveals, no-speech hearSentence fallback, example-sentence lines on word cards and reveals), when `charsUnlocked() && prog.mixChars`, each token renders by its character streak (`PC.sentenceTokenTier(streak, unlocked, mixChars)`). A SENTENCE_EXTRA token uses its `base` word's streak and displays its own characters.

| streak | rendering |
|---|---|
| 0–2 | pinyin only (unchanged) |
| 3–5 | `<ruby>字<rt>zì</rt></ruby>`, tone-coloured pinyin in the ruby |
| ≥ 6 | characters alone |

Each token keeps its `data-sent`/`data-widx` wrapper, so tap-to-hear works unchanged. The gap blank and the gap options stay pinyin. `showChars` keeps its meaning (the full character line beside every word/sentence) and is independent of mixing.

**Character-visibility rule, relaxed:** with `showChars` false, VOCAB characters still never appear in the DOM **except** (a) character-stage teach cards and character items (Learn drill, Review, Recall), (b) the Characters test, (c) mixed sentence tokens whose word has character streak ≥ 3, and (d) the path strip's 字 / 字4 stage labels (static UI glyphs, like the Words-tab icon). (a)–(c) exist only once characters have started; (d) is always shown, as part of the full path.

## Deviations

- **`n` field spells ü as `ü`, not `v`.** The real `data/hsk_vocab.js` (produced by the parallel vocab worker) uses the literal `ü` character in the numbered field (e.g. `n:"nü3er2"`, `n:"lü4"`), not the `v` substitute this spec's Data section describes. `normType`/`acceptTypeAnswer` treat `ü`, `v`, and `u:` as equivalent on both sides of the comparison, so this has no user-visible effect — "nv3er2", "nü3er2" and "nu:3er2"-style input all work — but code reading `n` directly (rather than through the helpers) should not assume `v`.
- **Placement vocab strata bucket sizes**: the spec's "8 + 40 = 48 items" is implemented as 16 buckets (L1×3, L2×3, L3×4, L4×6) alternating 2/3 items per bucket (8 buckets × 2 + 8 buckets × 3 = 40), rather than a fixed per-bucket count, since level sizes aren't evenly divisible.
- **Placement pass rule uses a rolling 3-bucket accuracy window, not a flat 85% (or fixed-misses) cutoff per bucket.** With only 2–3 items per bucket, judging each bucket in isolation makes a single lucky or unlucky guess decide the whole bucket (a flat 85% cutoff requires a perfect score at that size; a bare "misses ≤ 1" rule lets a 1-of-2 lucky guess pass). The final rule (`PC.placementStopIndex`): walking buckets in order, bucket *i* passes if the combined accuracy over buckets `max(0, i-2)..i` is ≥ 75% **and** bucket *i* itself has at least 1 right answer. Placement stops at the first failing bucket. This smooths out single-item noise while still requiring sustained performance, and a bucket can't pass purely on a good window if it personally got everything wrong.
- **`learnedWords()` unions completed-set words with words explicitly flagged `d` (drilled ahead of position), not "any word with a `prog.w` entry."** Drilling a Words-tab set ahead of the learner's current position (via the set pager) doesn't advance `prog.sets` for the skipped range, but the drilled words should still count as learned — so they're stamped `prog.w[word].d = 1` and `learnedWords()` includes them via that flag specifically. This matters for placement retakes: taking Placement again deletes every `prog.w` entry that is either placement-only-provisional-and-unreviewed (`prov && s <= 1`) or flagged `d`, before re-seeding from the new result — otherwise those leftover entries would resurrect words outside the freshly placed range through the union and the retake wouldn't actually reset anything.
- **Type-mode answer checking doesn't do general pinyin segmentation.** Rather than parsing arbitrary concatenated pinyin into syllables (ambiguous for neutral-tone runs, e.g. "zenmeyang"), `acceptTypeAnswer` builds the small set of acceptable normalized strings directly from the known-correct `n`/`py` fields (numbered form with every neutral-tone digit tried as `5`/`0`/omitted, plus the marked `py` form) and checks the user's normalized input against that set. This satisfies all documented variants without needing a dictionary-based segmenter, but means it cannot give partial credit or a smart per-syllable diff for input that's segmented differently than expected — the "type" drill's wrong-answer reveal just shows what was typed next to the correct marked pinyin, not a computed diff.
- **Valid-syllable table is hand-authored (~408 entries), not sourced from an external dataset.** It's a full initial×final combinatorial table built from standard Mandarin phonotactics (used only to validate that generated distractors are phonotactically plausible spellings — not that they're real dictionary words). A handful of very rare real syllables may be missing and it may accept a small number of implausible-but-well-formed strings; this doesn't affect correctness of the answer-checking (which is based on the real VOCAB data), only the quality of generated distractors.
- **Lesson/vocab drill counts are close-but-not-literal to the spec's session-step prose** (e.g. "drill 10 × read+tone" is implemented as 10 words × 2 item types = 20 drill items; Review mixes read/listen/tone roughly 40/30/30 rather than a fixed split).

### v2 (2026-09-17)

- **The `.w` (character) audit gates VOCAB word characters only, not the Sounds lessons' example characters.** `docs/PINYIN_SPEC.md`'s "characters never appear when `showChars` is false" is implemented for every render site that shows a vocabulary word's `w` field (Words list, teach cards, Progress weak-word list, drill reveals) via a shared `charSpan()` helper — but the Sounds tab's lesson tables (`data/pinyin_lessons.js` `rows[1]`, e.g. "妈" next to "mā") are unchanged, since that tab is explicitly "v1 lessons + reference chart, unchanged" and its example characters are pedagogical content about *sounds*, not the vocabulary-recognition cue the toggle is meant to hide. Extras' tone/type items (which do show `entry.w`, the VOCAB character) *are* gated: with `showChars` off, `toneItem`/`typeItem` fall back to audio + the toneless-pinyin subtitle instead of the character, so they stay usable and never leak a character.
- **Today's "Learn" step no longer interleaves Sounds lessons.** v1 taught the next undone Sounds lesson before vocab when one was pending; v2's Today path is vocab-only (Review → Learn → Listen → Recall), consistent with "Sounds removed from the path" — Sounds lessons are reachable only from their own tab, surfaced via the one-line first-time hint on Today.
- **Placement's "hear or read" choice per item is a per-item coin flip (50/50 when TTS is available), not a fixed split.** The spec says "hear/read → meaning items"; each of the 40 vocab items independently renders as a hear item (speaker glyph + audio) or a read item (pinyin shown) with `Math.random() < 0.5` (always read if no TTS voice is available), rather than a prescribed count of each.
- **`meaningOpts`/`pinyinOpts` take an explicit `pool` argument (`meaningOpts(entry, pool)`, `pinyinOpts(entry, pool)`) rather than closing over a global `VOCAB`.** `pinyin_core.js` has no DOM/global dependency (it's also required directly by the Node checks), so the app always calls them as `PC.meaningOpts(entry, VOCAB)` / `PC.pinyinOpts(entry, VOCAB)` — functionally what the spec names, just with the pool passed in like the pre-existing `distractors(entry, pool)`.
- **`pinyinOpts`'s "same syllable count" rule has a closest-count fallback.** The HSK 1–4 corpus has only one 4-syllable word ("公共汽车", bus) and no other 4-syllable word to draw distractors from, so a strict same-count filter would return 0 distractors for it. When the exact-syllable-count pool has fewer than 3 other words, `pinyinOpts` widens to the closest available syllable counts (3, then 5, etc.) instead of returning fewer than 3 options. This only triggers for that one word in the current corpus (verified by the 200-word check, which only requires an exact match when the corpus actually has 3+ other same-count words).
- **`meaningOpts`'s "avoid glosses sharing the first two words" rule has a small-pool fallback.** If fewer than 3 candidates survive the first-two-gloss-word dedup (only possible for a level with very few words and heavy gloss overlap — doesn't occur in the real ~1200-word corpus, verified by the 200-word check), it retries allowing repeated first-two-word keys among the picked distractors, still excluding the exact answer gloss, so the item always gets 3 options rather than failing to render.
- **Extras' items are unchanged from v1 (`toneItem`, `typeItem`), retired from every other screen but not otherwise rewritten**, since the spec calls them "v1 items, from learned words" for that tab specifically.
- **`pinyinOpts` also excludes gloss-twins of the answer** (e.g. 经历/经验, both "experience; to experience"), on top of the "same syllable count" rule the spec names. With the meaning shown and the learner picking the pinyin, a gloss-twin's pinyin would be an equally "correct" answer — the item would be ambiguous, not hard. Mirrors `meaningOpts`'s own-gloss exclusion.
- **Without a `zh-CN` speechSynthesis voice, hear items degrade to read items** (pinyin shown instead of the speaker glyph) rather than showing the character — `hasSpeech` is checked once at load, and `hearItem`'s no-speech fallback renders `PC.pyHTML(entry.n)` in the `.big` stimulus, same as `readItem`'s normal stimulus. The existing "no Chinese text-to-speech voice" notice still explains why.
- **Reveals no longer show the tone-contour glyph.** v1's reveal included `contourFor(entry.n)` next to the tone-coloured pinyin; v2's meaning-centred reveal (`revealBlock()`, used by hear/read/recall) is pinyin + meaning + characters-if-enabled only, since the contour glyph is a pronunciation aid orthogonal to meaning recall. `contourFor` is kept and still used by the Extras-only `toneItem`/`typeItem` reveals.
- **Data category fix: an `en` gloss must never embed a raw Chinese character.** 10 real VOCAB words leaked one (e.g. 你's "you (informal, as opposed to courteous 您)", 超市's "supermarket (abbr. for 超级市场)") — a Chinese cross-reference embedded by the upstream dataset inside an otherwise-English sense, which showed up as characters even with `showChars` off, since the app only ever gated the `w` field. Fixed at the source in `tools/build_vocab.py`'s `sanitize_gloss`, in three tiers, tried in order per clause (parenthetical, comma-fragment, or `;`-joined sense): (1) if the whole clause is nothing but a cross-reference lead-in ("opposite:", "abbr. for", "as opposed to", "also written", "same as", "variant of", "…equivalent of/to", etc.) plus the Chinese word it points to, drop the clause entirely; (2) else if a lead-in sits directly against a Chinese run *inside* a larger clause (呀: "particle equivalent to 啊 after a vowel, expressing…", with real content on both sides of the cross-reference), excise just the lead-in+character span, e.g. leaving "particle after a vowel, expressing…"; (3) else, if a Chinese run still remains — the source embedded it without one of the recognised lead-in phrases (虽然's second sense had "often used correlatively with 或 etc") — drop the whole clause rather than excising the character in place, since that would leave nonsense residue ("with or etc", where "or" reads as the English word). `build_en` falls back to the next candidate sense if sanitizing empties every one it tried (not observed on the real corpus, though dropping a whole clause under tier 3 did let a previously-truncated second sense of 有 fit under the 60-char gloss limit and surface for the first time — a correct side effect, not a bug). A defensive render-time guard, `PC.gloss(entry)`, is used at every site that displays or compares an `en` field, so a future un-sanitized data regression can't leak a character past the toggle again. Check 12 gates both the shipped data and the guard: a full-corpus scan for `/[一-鿿]/` (0 hits), a second scan for a dangling lead-in immediately before a clause boundary (0 hits outside an explicit 2-word allowlist — 对面 "(sitting) opposite; across (the street)" and 相反 "opposite; contrary", where "opposite" is hand-verified to be the genuine, CJK-free English gloss, not a leftover cross-reference), and a direct `PC.gloss()` unit test.
- **The header's live drill readout is `PC.gloss`'s render-time-guard sibling for progress display, not accuracy.** It no longer shows "right / seen" numbers — just "k left" plus a thin progress bar under the header tracking answered/total (both empty/zero outside a drill). The final per-drill accuracy ("X / Y") still shows once, on the drill's own "done" summary screen; `setScore`'s signature changed from `(right, seen, left)` to `(answered, total)` accordingly.
- **The speaker icon is one inline SVG (`speakerSVG(size)`), not an emoji**, used at three sizes: the big hear-item glyph, the small "replay" control (Extras' tone/type items, Sounds lessons), and a small tap-to-hear icon on Words-tab teach-card rows. The Sounds tab's own taplist buttons (`▶ word`, for lesson example words and the reference chart) are untouched, consistent with that tab being "unchanged" — they're a different, label-prefixed control, not a bare replay glyph.
- **Desktop (≥900px) drops `.wrap`'s viewport-height fill instead of the card's.** The spec's "must not stretch" is implemented by removing `.wrap`'s `min-height: 100dvh`-based rule inside the existing 900px media query, rather than touching `.card`'s `flex:1 1 auto` — the card still grows to fill `.wrap`, but `.wrap` itself now only sizes to its content on a wide screen, so there's no extra height for the card to stretch into. On phone, the same flex chain now centers a new `.drill-body` wrapper (prompt+stimulus+options+reveal, or Today's plan block) via `flex:1 1 auto` + `justify-content:center`, with the pinned action button as a normal (non-growing) sibling after it — a flex-grow content wrapper followed by a plain sibling, rather than competing `margin:auto` on both, since two independent auto-margins split the free space three ways instead of centering the content block.
- **Hints never tell the learner which tab to visit — they act directly (user category fix).** Grepped the app for "in the X tab" / "go to" / "use the X tab" and changed every hit:
  - Today's two first-time hints (`todayRender`) now carry the action itself: "New here? Placement finds where to start" → **Take the placement test** calls a new `enterPlacementFromToday()`, which switches the tab bar to Test and runs the same `startPlacement()` (pulled out of `placeRender`'s click handler so both call sites share it) that Test's own placement screen uses; placement's existing "Go to Today" end screen already returns here regardless of entry point. "New to pinyin?" → **Learn how to read it** calls `enterFirstSoundsLessonFromToday()`, which switches the tab bar to Sounds and opens `LESSONS[0]` via `lessonTeach()` directly, with a `backToToday` callback wired as both its `onDone` and `onBack` so finishing or backing out of the lesson returns to Today either way.
  - Both hints now hide by real state instead of a "Got it" dismiss button: `prog.placedOnce` (set in `placeResult()`, so it's stamped whether placement was entered from Today or Test) and `prog.soundsOpened` (set once, in `lessonTeach()` itself — the one function both the Sounds tab and the new Today shortcut call — so *opening* any lesson hides the hint, not finishing one). `prog.dismissedSoundsHint` is retired; `validateProgShape` still accepts it on import (an old export shouldn't fail to load) but nothing in the app writes or reads it anymore.
  - Test/Extras' "Learn a few words first (Today or Words tab)" `alert()`s (two call sites, the Listen/Recall gate and the Type/Tones gate) dropped the tab pointer — now just "Learn a few words first." — since an `alert()` can't itself carry a follow-up action without a larger redesign of that gate.
  - Placement's "everything covered — go straight to Words and pick a set" end-state line dropped the "go straight to Words" pointer, for the same reason; the "Go to Today" button on that same screen is left as-is since it already **is** the direct action, not a hint pointing at one.
- **`build_en`'s 2nd-sense join now skips any register-tagged sense** — "(bound form)", "(literary)", "(dialect)", "(archaic)", "(old)", "(coll.)" — not just "(bound form)" (which was already deprioritized in ranking, but not excluded from joining). A register-tagged sense is a real but rare/technical/dated reading, fine to show alone when it's the only sense a word has, but not worth joining onto a perfectly good plain sense just because the pair happened to fit under the 60-char budget — which is exactly what let 有's "(bound form) having; with; -ful; -ed; -al" get joined onto "to have; there is" after tier-3 CJK sanitization shortened it (see the data-category-fix entry above). Regenerating with this rule changed 9 glosses total, all a tagged addendum being dropped (不, 有, 猫, 雪, 爷爷, 帅, 梦, 输) or, for 别, a *different*, more useful untagged sense ("don't ...!") taking the now-open second-sense slot instead of the previously-unrecognized "(literary) to differentiate; to distinguish".

### Phase 2 — Sentences (2026-09-17)

- **`hearSentence`/`readSentence`/`gapSentence` live in the app (`src/pinyin_app.html`), not `pinyin_core.js`.** Following the existing `hearItem`/`readItem`/`recallItem` precedent, these builders close over app state (`say()`, `markSentence()`, DOM helpers) and can't be pure. Only the pieces that genuinely have no DOM/app dependency — `sentenceOpts`, `gapOpts`, plus their shared helpers `sentenceTokens`, `gapCandidateIndices`, `guessTone`, and the `SENTENCE_FUNCTION_WORDS` list — are in core, where they're directly Node-testable (checks 13–17).
- **EXTRA-compound tone coloring uses a whole-word, last-syllable heuristic (`PC.guessTone`), not per-syllable coloring.** VOCAB words carry a numbered pinyin field (`n`) that `pyHTML` colors syllable-by-syllable; `SENTENCE_EXTRA` tokens only carry marked pinyin (no numbered form, since they're compounds like 夏天/哪儿/你们/这个 rather than dictionary headwords). Rather than build a second segmenter just for these, `guessTone` reverse-scans the marked text for the last tone-marked vowel and colors the entire token by that one tone. This is a readability aid, not a pronunciation drill, so the minor imprecision (a multi-syllable EXTRA token gets one color, not one per syllable) doesn't affect any answer-checking.
- **Sentence-initial capitalization is a regex post-process on the per-word `pyHTML` output**, not a data-level change to `SENTENCES[i].py`. The stored pinyin is lowercase throughout (as VOCAB's `py` field is); `sentencePyHTML` upper-cases the first letter inside the first word's rendered span after building it, via `PC.capitalizeFirstSpan` (a small pure core helper, anchored to the very start of the HTML fragment — see the fix-batch entry below for why it isn't just an inline regex), so the underlying data and every other consumer (TTS input, `sentenceTokens` alignment, checks) still see the plain lowercase string.
- **"Placed past its level" is `currentLevel() > sentence.lv`, where `currentLevel()` is `nextNewSet()?.lv`, or 5 if every level is fully learned.** The spec says a sentence is available when its words are learned "or the learner has placed past its level" — `nextNewSet()` already identifies the next not-yet-learned set and its level for Today's Learn step, so reusing it here (rather than adding a second notion of "current level") means a learner who has finished HSK 1–3 and is partway through HSK 4 sees all HSK 1–3 sentences as available even for the rare sentence containing a not-yet-learned HSK 3 word, consistent with how `learnedWords()` already works for vocabulary items.
- **"Words → a word's reveal/teach card lists up to 2 sentences" is implemented at both `revealBlock()` (the drill reveal shown after every hear/read/recall answer) and `vocabTeach()`'s per-word teach rows** (the Words-tab/Learn-step "teach card" proper) — both are reasonably "a word's card" and a learner benefits from seeing example sentences in either place, so rather than picking one the same `exampleSentencesHTML(entry)` helper (via `wordExampleSentences(w, 2)`, first-2-matches order, no ranking) is appended to both.
- **`gapOpts` reuses the identical closest-syllable-count fallback tier as `pinyinOpts`** (see the v2 Deviations entry above for 公共汽车) for the same reason: a gap answer word with no other same-syllable-count VOCAB peer would otherwise get fewer than 3 distractor options. Check 16 mirrors check 10's `exactPoolSize<3` relaxation.
- **Progress migration additionally seeds `prog.s = {}`** in `PC.migrateProg` — any progress object missing the field (a real v1 export, or a v2 export from before Phase 2 shipped) gets an empty sentence-progress map rather than failing `validateProgShape` or crashing on first sentence-drill write.

### Phase 2 fix batch (2026-09-17, browser review)

- **"No `alert()` except the destructive Reset confirm" (category fix).** Audited every `alert()`/`confirm()` call: the Words-tab "review" gate (hidden the button instead, since "Drill this set" on the same panel is already the direct action), Test's Listen/Recall/Sentences-20 gates and Extras' Type/Tones gate (all "Learn a few words first.") now render an inline `.stmt` note with a **Take the placement test** button wired to `enterPlacementFromToday()` — placement seeds `prog.sets`, the fastest real way past an 8-learned-word gate, same path Today's own hint uses — and the two progress-import validation messages write into an inline `#impErr` box next to the paste/upload controls instead of popping an alert. Only `confirm("Reset all progress?…")` remains.

Each button now reads `Math.min(20, pool.length)`.
- **`dnext()`'s drill-done screen no longer inherits the last item's 100% header progress bar.** `setScore(D.seen, D.seen + D.q.length)` was called unconditionally before checking whether the queue was empty, so the done screen (nothing "left", nothing "of") kept showing the previous item's full bar. Fixed by moving that call after the empty-queue check and calling `setScore(0, 0)` inside the done branch instead — every other `#panel`-writing site already did this at its own top; this was the one gap.
- **Desktop (≥900px) tab bar is now in the normal document flow, not fixed to the viewport bottom.** A short card (a one-line Today plan, a single drill item) left 280–550px of bare background between the card and a viewport-pinned bar. `.tabs` switches to `position: static` inside the existing 900px media query, same width, centered under the card with a small top margin and a full border/radius (previously top-border-only, flush with the screen edge); `body`'s bottom padding (there to clear the fixed bar) drops to a small flat value. Phone is untouched — the base `.tabs` rule (line 124) stays `position: fixed`.
- **`gapCandidateIndices` also excludes a word that recurs elsewhere in the same sentence.** Blanking one occurrence of a repeated content word would leave the answer sitting in plain sight at its other occurrence(s) in the same rendered sentence — a real leak the original rule (function-word + level check only) didn't cover. Fixed by counting each word's occurrences in `sentence.words` and skipping any index whose word appears more than once, gated in core and checked (corpus-wide, plus a synthetic duplicate-word regression case) in the node suite.
- **Sentence-initial capitalization bug: `sentencePyHTML` capitalized the wrong syllable when the first syllable's vowel carried a tone mark** (阿姨's "āyí" rendered as "āYí"). The old inline regex, `/>([a-zü])/i`, wasn't anchored to the string's start — it scanned for the first `>` followed by a plain ASCII/ü letter anywhere in the rendered HTML, and since a tone-marked vowel like "ā" isn't in `[a-zü]`, it skipped past the first syllable's own span and matched the *second* syllable's plain consonant instead. Fixed by extracting a small pure helper, `PC.capitalizeFirstSpan(html)`, anchored to the literal start of the fragment (`/^(<[^>]+>)([^<])/`) so it can only ever touch the character immediately after the opening tag, regardless of whether it carries a diacritic. Gated by a full-corpus regression check (18) that mirrors the render pipeline in Node and compares the tag-stripped output against each sentence's stored `py`.
- **Sentence tap-to-hear no longer puts any Chinese text in the DOM, even inside a `data-*` attribute.** The original `data-say="${word}"` (per-word spans) and `data-say="${sentence.zh}"` (whole-sentence example rows) embedded the actual character string directly in markup — invisible on screen with `showChars` off, but still present for a raw DOM grep, which the character-gating acceptance criterion doesn't allow. Fixed by keying taps off two numeric attributes instead — `data-sent` (a `SENTENCES` array index, via `sentenceIndexOf()`) and, for a per-word tap, `data-widx` (a `words[]` index) — and resolving the actual string to speak only in memory, at click time, from the in-memory `SENTENCES` array. `wireSayTaps(root)` is now a single delegated `click` listener per container using `e.target.closest("[data-sent]")`, so a tap on a word span (which has both attributes) resolves to just that word even though it sits inside a whole-sentence row (which has only `data-sent`) — `closest()` picks the nearest match, word before row. `wireSayTaps` also now runs on the drill-done screen's miss-summary HTML (`dnext`'s done branch), which embeds missed items' own reveal HTML but previously never wired it, leaving any sentence tap targets there dead.
- **`availableSentences()` no longer recomputes `learnedWords()`/`currentLevel()` once per sentence.** Both are themselves O(VOCAB) scans; calling them inside the `.filter()` callback made the whole function O(SENTENCES × VOCAB) (~4M ops on the full corpus) for what should be a cheap per-render lookup. The learned-word `Set` and current level are now computed once per call and threaded through `sentenceAvailable(sentence, lwSet, curLv)`/`sentenceWordsLearned(sentence, lwSet)` as parameters instead of each rebuilding its own.
- **不's gloss gets a hand-picked override ("no; not"), not just build_en's automatic rule.** After the register-tag join fix (previous entry), build_en correctly stops joining 不's "(bound form) not; un-" onto its first sense, leaving only the source's own "no; not so" — technically correct, but an over-literal gloss for HSK 1's basic negation particle. `GLOSS_OVERRIDE` in `tools/build_vocab.py` is a new, small, word-keyed override map (currently one entry) applied after `build_en`, for exactly this kind of case: the automatic rules picked a defensible sense, but the plainest English gloss needs a human call the source text doesn't make for you. Documented inline with the reasoning, not silently overwritten.
- **Stale-build guard: `tests/pinyin_checks.js` now rebuilds the app to a scratch file via the real `build.sh` and diffs it against the shipped `hsk_pinyin.html`/`index.html` (check 0), failing the whole suite if they differ.** Every other check runs against `src/`/`data/` source files directly, never the shipped bundle, so a code/data edit made without a following `sh build.sh` could previously pass every check while shipping a stale bundle. `build.sh`'s `OUT`/`INDEX` variables are now `${VAR:-default}`-overridable via environment so the check can redirect the rebuild to a temp path without touching the real output files as a side effect of just running the test suite.
